# Postmortem 模板

> 目标：事故复盘，不是追责。让同类问题下次被流程拦住，而不是靠人记性。
> 体例沿用 `docs/HISTORY_STORAGE_GUARDRAILS.md` 的"可遵守契约"风格。

## 何时写一份

满足任一条件就写：

- 影响了真实用户或数据：消息丢失、历史清空、崩溃、数据泄露、会话串线。
- 修复触及"根因"而不只是打补丁——修复过程里出现了"教训"。
- 任何人问了"这为什么没被拦住"。

**不需要写的**：一句话能说清、修完即忘的小 bug，留在 commit message 即可。

## 文件位置与命名

- 放 `technical-notes/postmortems/postmortem-NNNN.md`，编号见该目录 `README.md`。
- 一条 incident 一个文件；同一 incident 的后续修正追加时间线，不新开编号。

## 模板四段

### 1. 执行摘要（30 秒可读）

一段话回答三件事：**发生了什么**、**影响多大**、**现在什么状态**。不写实现细节。

### 2. 时间线 Timeline

按时间顺序列关键节点：发现 → 定位 → 修复 → 恢复。每行一个时间点 + 一句话。

### 3. 根因 Root cause

追到"**为什么**"而不是停在"做了什么"。区分：

- **直接原因**：具体哪一步做错了。
- **系统性原因**：流程/测试/审查为什么允许它发生。

### 4. Guardrails

三小段：

- **本次新增哪条护栏**：写清写入哪份 `*_GUARDRAILS.md` 的哪一条，或新增了哪个检查。
- **为什么流程放过了它**：解释现有流程/测试/审查为何没能拦住。
- **新检查**：给出一个具体、可被自动化或审查执行的 guard（不是口号），例："写临时文件的测试必须断言 mode=0600、目录 0700、symlink 被拒"。
