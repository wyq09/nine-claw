# Self-Improving Agent

你负责把“出错一次”转成“下次更稳”，并把可复用经验沉淀进 NineClaw 的智能体工作区。

## 目标

1. 遇到错误、纠正、缺口、改进机会时，主动记录，而不是只在当前会话里记住。
2. 把原始事件、短期上下文、稳定记忆、明确决策分层存储。
3. 在后续相似任务里，优先回看已有提升记录，避免重复犯错。

## 何时触发

出现下面任一情况就应启用本技能：

1. 命令、工具、API、外部服务调用失败。
2. 用户明确纠正你，例如“不是这样”“你理解错了”“按这个来”。
3. 你发现自己的知识、假设、路径选择过时或错误。
4. 用户提出当前系统还不支持的新能力或新流程。
5. 你总结出更稳、更省事、更可复用的工作方式。
6. 开始复杂任务前，需要先回顾该智能体之前沉淀过的经验。

## NineClaw 存储规则

本技能必须优先使用 NineClaw 已有的工作区记忆结构，不要另起一套散乱文件。

### 写入位置

- `agents/<agent-id>/memory/YYYY-MM-DD.md`
  记录原始事件、失败现场、用户原话、你当时的处理结果。
- `agents/<agent-id>/WORKING.md`
  记录当前还在追踪的坑、待补动作、当前轮应立即记住的上下文。
- `agents/<agent-id>/MEMORY.md`
  记录已经确认、以后大概率还会复用的稳定经验。
- `agents/<agent-id>/DECISIONS.md`
  记录明确决策、统一规范、以后都要遵守的规则。
- `agents/<agent-id>/memory/categories/*.md`
  记录分类后的记忆分片，供后续按问题抽取。

### 分类原则

根据内容把经验沉淀到一个或多个分类记忆里：

- `user_profile`
  用户身份、职责、组织背景、角色信息。
- `preferences`
  用户偏好、输出风格、格式要求、称呼习惯、禁忌。
- `projects`
  项目背景、产品上下文、代码库信息、长期任务目标。
- `commitments`
  待办、截止时间、后续动作、提醒事项。
- `decisions`
  已确认的方案、统一标准、以后默认执行的规则。
- `relationships`
  相关人、团队、客户、负责人、合作对象。
- `general`
  无法更细分但值得保留的稳定经验。

## 记录策略

### 失败类

当命令、工具或外部服务失败时：

1. 把原始错误和上下文写进当天 `memory/YYYY-MM-DD.md`。
2. 如果这个坑短期内还会继续处理，把当前结论写进 `WORKING.md`。
3. 如果已经知道稳定规避方式，把规避规则提炼到 `MEMORY.md` 或 `DECISIONS.md`。

### 用户纠正类

当用户纠正你时：

1. 先承认并采用用户给出的正确信息。
2. 判断这是偏好、项目事实、还是决策规则。
3. 把“旧认知错在哪里，新规则是什么”沉淀到对应分类记忆。
4. 如果以后必须严格遵守，额外写入 `DECISIONS.md`。

### 能力缺口类

当用户提出系统当前没有的能力时：

1. 在 daily log 里记录用户需求和触发场景。
2. 在 `WORKING.md` 里记录它为什么重要、后续建议怎么补。
3. 如果这个缺口属于某个长期项目或流程，把它写入 `projects` 或 `commitments` 分类记忆。

### 最佳实践类

当你发现更稳的方式时：

1. 先确认它不是一次性的偶然技巧。
2. 若可复用，写入 `MEMORY.md`。
3. 若它已经成为默认工作规则，写入 `DECISIONS.md`。
4. 若它和用户偏好强相关，同时写入对应分类记忆。

## 查询与抽取规则

后续回答问题前，必须按下面规则利用这些提升记录：

1. 遇到“之前”“上次”“继续”“还记得吗”“按我们之前说的”“我的偏好”“项目背景”“之前的决定”这类问题时，优先查看相关分类记忆。
2. 若问题是关于格式、口吻、称呼、输出方式，优先看 `preferences`。
3. 若问题是关于项目、仓库、长期目标，优先看 `projects`。
4. 若问题是关于下一步、提醒、截止时间，优先看 `commitments`。
5. 若问题是关于已经定下来的方案或规范，优先看 `decisions`。
6. 若分类记忆与旧会话印象冲突，以分类记忆和 `MEMORY.md` / `DECISIONS.md` 为准。
7. 若没有查到稳定记忆，明确说“当前持久化记忆里没有这条”，不要编造。

## 记录质量要求

- 不要把每句闲聊都升级成长期记忆。
- 优先保留“以后仍然有用”的事实、规则、偏好、失败教训。
- 原始现场保留在 daily log，稳定提炼再进入 `MEMORY.md` / `DECISIONS.md` / 分类记忆。
- 新记录应尽量短、准、可复用，避免写成长篇流水账。
- 如果一条经验已经存在，优先补充和合并，不要重复造相同条目。

## 对用户的表现

- 默认不要把“我正在记日志”“我刚写了某个 md 文件”当成回复主体。
- 只有用户明确问到记忆、复盘、沉淀机制时，才说明你更新了哪些长期记忆。
- 重点是让后续行为更稳，而不是把内部存档过程表演给用户看。
