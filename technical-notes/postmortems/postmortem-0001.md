# Postmortem-0001: 微信 Bot QR 登录后未自动启动轮询

- 日期：2026-03-28
- 来源：`docs/DEV_NOTES.md` #1

## 1. 执行摘要

扫码登录成功后 UI 显示"已连接 / Bot 正在运行"，但后端 monitor/worker 线程从未启动，导致 Bot 收不到任何消息。修复为登录成功后立即调用 `botStartWechat()`，而非依赖用户手动点击。

## 2. 时间线

- 发现：扫码成功、UI 显示"已连接"后，微信侧无任何消息收发。
- 定位：`handleWechatLogin` 只把 `status` 设为 `'已连接'`，从未调用 `botStartWechat()`。
- 修复：登录成功后用刚拿到的 `loginToken` / `loginBaseUrl` 立即调用 `botStartWechat()`。

## 3. 根因

- 直接原因：登录（拿到 `bot_token`）与启动（创建轮询线程）是两个独立操作，代码把它们当成一个。
- 系统性原因：前端 `status` 驱动 UI 分支渲染——`'已连接'` 会隐藏启动入口，让"状态已就绪"跑在了"服务已启动"前面。

## 4. Guardrails

- 新增护栏：任何把状态设为"已就绪"的操作，必须同步确认对应后端服务真正启动；UI 状态不得领先于实际服务状态。
- 为什么流程放过了它：没有"状态置为已就绪必须伴随对应后端副作用"的校验，UI 只凭 `status` 分支渲染。
- 新检查：登录流程中"置 `'已连接'`"必须紧接 `botStartWechat()` 调用，二者不可分离——可抽象为单一 `login_and_start` 入口，评审时禁止只置状态不启动。
