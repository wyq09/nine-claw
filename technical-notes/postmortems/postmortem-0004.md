# Postmortem-0004: iLink 协议关键约束

- 来源：`docs/DEV_NOTES.md` #4

## 1. 执行摘要

iLink 协议有多条强约束：`context_token` 回复时必须原样回传、单条消息约 3900 字符需分片、`errcode -14` 表示会话过期、只处理 `MSG_TYPE_USER`。违反会导致消息投递错乱或静默失败。此为约束文档，非事故。

## 2. 时间线

- 接入 iLink → 踩坑（token 未回传导致投递错乱、超长未分片、会话过期未重登）→ 沉淀约束清单。

## 3. 根因

`context_token` 等协议字段是隐式契约——违反不会立即报错，而是静默投递失败或串到错误会话；约束只存在于文档，代码层不强制。

## 4. Guardrails

- 新增护栏：回复必须使用入站消息携带的 `context_token`；超长回复按字符边界分片（关联 postmortem-0005）。
- 为什么流程放过了它：协议约束依赖开发者记忆，缺少代码层断言或契约测试。
- 新检查：回复路径断言 `context_token` 非空且原样回传；分片函数必须走字符边界并有超长中文测试。
